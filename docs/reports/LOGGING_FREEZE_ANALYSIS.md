# Анализ фризов из-за логирования

## Дата: 2025-12-15

---

## 🔴 ПРОБЛЕМА: Фризы на 1 секунду при скорости 10-15

### Симптомы:
- Мяч и платформа замирают на ~1 секунду
- Происходит при скорости мяча 10-15
- Игра продолжается после фриза

---

## 🔍 НАЙДЕННАЯ ПРИЧИНА: Синхронная ротация файлов логов

### Проблема #1: RotatingLinesFileHandler блокирует основной поток

**Код в `ai/rotating_file_handler.py`:**
```python
def emit(self, record: logging.LogRecord) -> None:
    # Проверяем, нужно ли создать новый файл
    if self.current_line_count >= self.max_lines:  # 500 строк
        self._rotate_file()  # ❌ СИНХРОННАЯ ОПЕРАЦИЯ!
    
    # Записываем запись
    super().emit(record)
    self.current_line_count += 1

def _rotate_file(self) -> None:
    """Создает новый файл для логирования."""
    self.close()      # ❌ Закрытие файла - блокирует поток!
    self.current_file_number += 1
    self.current_line_count = 0
    new_filename = self._get_current_filename()
    self.baseFilename = new_filename
    self.stream = self._open()  # ❌ Открытие файла - блокирует поток!
```

**Что происходит:**
1. При достижении 500 строк вызывается `_rotate_file()`
2. `self.close()` - синхронное закрытие файла (блокирует поток)
3. `self._open()` - синхронное открытие нового файла (блокирует поток)
4. Это занимает ~1 секунду и блокирует весь игровой цикл!

### Проблема #2: Высокая частота логирования

**Статистика:**
- В `paddle_movement.py`: **69 вызовов** `logger.debug`
- При скорости 10-15: много вызовов `move_paddle_towards` за секунду
- Каждый вызов генерирует несколько логов
- 500 строк накапливаются **очень быстро** (за 5-10 секунд игры)

**Расчет:**
- При 60 FPS: 60 кадров/секунду
- Каждый кадр может генерировать 2-5 логов
- 60 × 3 = 180 логов/секунду
- 500 строк / 180 = **2.8 секунды до ротации**
- При скорости 10-15 ротация происходит каждые 2-3 секунды!

---

### Проблема #3: Синхронная запись в файл

**Текущая реализация:**
- Все логи пишутся **синхронно** в файл в основном потоке
- Каждый `logger.debug()` вызывает `FileHandler.emit()`
- `FileHandler.emit()` делает синхронную запись на диск
- При высокой частоте логирования это создает задержки

## ✅ РЕШЕНИЯ

### Решение 1: Увеличить max_lines (БЫСТРОЕ ИСПРАВЛЕНИЕ)

**Изменение:**
- Увеличить `max_lines` с 500 до 2000-5000
- Это уменьшит частоту ротации файлов

**Плюсы:**
- Простое изменение (1 строка кода)
- Сразу уменьшит частоту фризов

**Минусы:**
- Не решает проблему полностью (фризы все равно будут, но реже)
- Больше логов в одном файле

---

### Решение 2: Изменить уровень логирования (БЫСТРОЕ ИСПРАВЛЕНИЕ)

**Изменение:**
- Изменить `LOG_LEVEL` с `'DEBUG'` на `'INFO'` в `ai/logging_config.py`
- Это уменьшит количество логов в 10-20 раз

**Плюсы:**
- Простое изменение (1 строка кода)
- Сразу уменьшит частоту логирования
- Меньше нагрузка на диск

**Минусы:**
- Меньше информации для отладки

---

### Решение 3: Асинхронная ротация файлов (ПОЛНОЕ РЕШЕНИЕ)

**Изменение:**
- Использовать `threading` для ротации файлов в фоновом потоке
- Не блокировать основной поток

**Плюсы:**
- Полностью решает проблему фризов
- Не блокирует игровой цикл

**Минусы:**
- Более сложная реализация
- Требует изменений в `RotatingLinesFileHandler`

---

### Решение 4: Буферизация логов (ПОЛНОЕ РЕШЕНИЕ)

**Изменение:**
- Использовать `BufferedLogger` (уже есть в коде)
- Накапливать логи в буфере и записывать пакетами

**Плюсы:**
- Уменьшает количество операций записи на диск
- Улучшает производительность

**Минусы:**
- Требует изменений в инициализации логирования
- Может потерять логи при краше (если буфер не сброшен)

---
